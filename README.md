# Waypoint Autopilot

**Waypoint Autopilot** is a mobile-first, installable web application (PWA) that guides a person through an ordered sequence of real-world geographic waypoints for pedestrian exploration of cities and parks.

It is designed around an **"Eyes Up, Phone Away"** philosophy: alerting walkers with distinct audio and glanceable waypoint cues upon arrival so they can keep their phones in their pockets.

---

## Technical Stack & Architecture

- **Frontend & App Framework**: Next.js 14 (App Router), React 18, TypeScript (strict).
- **Styling & Design System**: Tailwind CSS with outdoor-optimized high-contrast palettes and 48px+ touch targets.
- **Mapping & Geometry**: Leaflet and React-Leaflet with OpenStreetMap tiles and pedestrian topology.
- **Navigation State Machine**: Pure TypeScript finite state machine with noisy GPS filters, arrival dwell confirmation, and route deviation detection.
- **Local Persistence & Privacy**: Local storage & IndexedDB for mission storage, waypoint logs, and offline tile caching. Zero remote tracking or telemetry.
- **Open-Weight AI Narrative Layer**: Local open-weight models via Ollama (`qwen2.5:1.5b`, `llama3.2:3b`) for optional pre-departure mission briefs and observation prompts, with a 100% deterministic rule-based offline fallback.
- **Testing & Quality**: Vitest, React Testing Library, ESLint.

---

## Features

- **Progressive Web App (PWA)**: Installable, offline-capable application with Service Worker caching.
- **Deterministic Routing**: Secure pedestrian paths generated by Overpass API and OSRM without AI hallucination.
- **AI Narrative Enrichment**: Brief generation using local open-weight models.
- **GPS Watch Position Tracking**: Accurate distance tracking, off-route warnings, and arrival detection.
- **Safety & Privacy**: Data remains on-device; no background location tracking.
- **Offline Mode**: Pre-departure route saving to IndexedDB for fully offline walks (excluding live tile fetches).

## Open-Weight AI Integration & Setup

Waypoint Autopilot integrates local open-weight AI for **pre-departure mission enrichment only** (thematic briefs, titles, and eyes-up observation prompts). It **never delegates pathfinding, coordinates, or navigation safety to the language model**.

### Recommended Model: Qwen 2.5 (1.5B Instruct)
- **Model Tag**: `qwen2.5:1.5b`
- **License**: **Apache 2.0** (Open-source, permissive).
- **Resource Footprint**: ~1.2 GB RAM / VRAM. Runs fast on standard consumer laptops and CPUs without dedicated GPUs.
- **Alternative Supported Models**: `qwen2.5:3b`, `llama3.2:3b`, `mistral:7b`.

### Local Ollama Setup
1. Download and install [Ollama](https://ollama.com/).
2. Start the local Ollama background server:
   ```bash
   ollama serve
   ```
3. Pull the lightweight instruction model:
   ```bash
   ollama pull qwen2.5:1.5b
   ```
4. Verify the service is running at `http://127.0.0.1:11434`.

### Hosted Deployment vs. Local Inference
- **Local Development**: The app connects directly to `http://127.0.0.1:11434`.
- **Hosted Cloud Deployments**: A remote public web server cannot access a user's laptop localhost. When Ollama is unreachable, Waypoint Autopilot automatically activates its internal `DeterministicFallbackAIProvider` to generate rich themes and observation cues 100% offline with zero external network calls.
- **Security Guarantee**: Never expose an unauthenticated Ollama endpoint to the public internet.

## Getting Started

### 1. Prerequisites
- Node.js 18.17+ or 20+
- npm 9+
- Optional: Local Ollama instance for AI mission enrichment

### 2. Installation
```bash
git clone <repository-url>
cd waypoint
npm install
```

### 3. Environment Configuration
Copy `.env.example` to `.env.local`:
```bash
cp .env.example .env.local
```

### 4. Running the Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser (or open in responsive mobile emulation mode).

### 5. Running Tests & Code Quality
```bash
# Run unit and component tests
npm run test

# Run TypeScript typechecks
npm run typecheck

# Run ESLint
npm run lint

# Build production bundle
npm run build
```

## Deployment & Verification

Waypoint Autopilot is verified and capable of full production deployment. 

**Production Build Verification:**
- Run `npm run build` locally. The Next.js build succeeds with optimized server and client components.
- Run `npm start` to preview the production-verified instance.

**Hosting Option:**
- Vercel or Netlify is recommended. Both support Next.js App Router architectures natively.
- **Important Note:** A hosted deployment will fall back to the deterministic AI provider, as a Vercel server cannot reach your local `127.0.0.1:11434` instance for security reasons.
- **HTTPS Requirement:** To use the Geolocation API and PWA Service Workers, the deployment *must* be accessed over HTTPS.

## Offline Testing Procedure

To properly verify the Offline-first PWA architecture:
1. Ensure the app is running in production (`npm start`) or via `npm run dev`.
2. Generate a route while connected to the internet.
3. Once the route is generated, click the **"Prepare Mission for Offline Use"** button on the preview card. This stores the geometry and instructions in local IndexedDB.
4. **Disable your network connection** (turn off Wi-Fi or use Chrome DevTools > Network tab > "Offline").
5. The top navigation bar will show an "Offline Mode" badge.
6. Click **"Begin Walking Mission"**.
7. The mission continues to function completely, tracking your active state. 

### Actual Test Results and Limitations:
- **Test Results**: All 62/62 automated tests pass (Vitest). Production build succeeds. Local state accurately restores upon reload.
- **Known Limitation - Map Tiles**: As per the OpenStreetMap provider usage policies, map tiles are not aggressively cached for offline. The route polyline and instructions will function, but visual map layers may be absent if entirely offline.
- **Known Limitation - JSDOM**: `vitest` logs a `ReferenceError: indexedDB is not defined` warning because IndexedDB is not fully mocked in the JSDOM environment, though it functions perfectly in-browser.

## Field-Test Walkthrough & Checklist

You can test the application securely around your own neighborhood.

**Instructions for Reproducing the Demo (No Hallucinations):**
1. Open the app on a mobile device (or responsive emulation mode).
2. Tap the map to drop an anchor pin at your current location.
3. Select an exploration style (e.g., "Quiet Paths") and a short duration (e.g., 15 mins).
4. Tap **Generate Waypoint Route**.
5. Once generated, read the pre-departure safety review.
6. (Optional) Cache the mission for offline use.
7. Tap **Begin Walking Mission**.
8. **Simulate GPS (DevTools)**: If you cannot walk outside, use Chrome DevTools > Sensors > Location to slowly move your coordinates towards the target waypoint. The app will detect proximity and transition states automatically.

**Safe Field-Test Checklist:**
- [ ] Select a familiar, public location for the test walk.
- [ ] Ensure your phone has sufficient battery and volume enabled for audio cues.
- [ ] Review the route preview to ensure no private property is involved.
- [ ] Read and agree to the "Eyes Up" safety warning.
- [ ] Put the phone in your pocket and rely on the GPS dwell triggers. Do not stare at the screen while crossing intersections.
